# generic-parser v3 沙盒 — 設計規格

v2 的路線是「盡量在 UI 上把話說完」。v3 反過來：**把解釋變成看得見的狀態，然後把解釋刪掉。**

一條總原則：**保留指令，刪除解釋。**「你現在該做什麼」留在畫面上；「為什麼會這樣」一律由視覺承擔，不寫字。

平台：**桌機 only**。hover 預覽是 v3 最有價值的機制，不為手機犧牲它。

---

## 1. 演算法：union 骨幹，沒有 descendant search

分歧點一律用 union 處理，`//` 與 extra predicate **在 v3 完全不存在**。

```
(./chainA | ./chainB)/共同結尾
```

XPath 1.0 限制（已實測）：`(A|B)/suffix` 合法，`a/(b|c)` 不合法 —— **括號必須提到最左**。
一側耗盡時該分支寫成 `.`（`(./aside/div | .)/div/span[2]` 可跑）。

**為什麼是 union 不是 descendant：**

1. union 只用使用者真的給過的證據；descendant 是工具替他發明一個沒看過的推論，再發明 predicate 補救。
2. union 的失敗是**漏抓**（藍框少了，看得見，修法是再點一個範例）；descendant 的失敗是**誤抓**（垃圾混在結果裏，看不見）。寧可漏抓。
3. 砍掉 descendant 就砍掉整棵 extra predicate 的決策子樹。
4. union 天然支援 N≥3：「漏了就再加一個範例」。

**代價與補救**：頁面有多種巢狀變體時，使用者不知道自己漏了什麼。內部跑一支 `.//共同結尾` 探針比對命中集合，多出來的就提示「還有 N 筆長得不太一樣」，點下去**從那 N 筆裏挑一個當第三個範例、長出第三條分支**（不是切換成 descendant）。
噪音防護：只在 `多出來筆數 ≤ 目前命中數` 時才顯示。**此項優先度低，可延後評估。**

## 2. 幾何

```
綠框 ─────────── NCA ═══分岔═══ 共同結尾 ─────── 紅框 ─── 原始點擊處
     兩路徑完全共用        兩條         形狀共用
```

- 綠框 = 求值的根，**不在查詢式裏**（`chain = segsUp(nca, green)` 不含 green）→ 邊界落在綠框 pill 的**右側縫隙**
- 紅框 = `tail` 的最後一段，是被命中的東西本身 → 邊界落在紅框 pill 的**右側縫隙**
- NCA 由範例決定，紅框在自己子樹內移動時 **NCA 不變**，是線上的固定樞紐
- 綠框可動範圍 `[root, NCA]`、紅框 `[分岔對齊層, 原始點擊處]`，兩者不重疊且首尾相接 → **它們在同一條線上**

## 3. 版面：兩條軌道

**一個問題只在一條軌道上回答。**

```
                          ┌ ■* ■  ┐
上軌   ■  ■  ■  ■  ■1 ────┤       ├──── ■* ■        每一節的鬆緊
                          └ ■* ■  ┘
下軌   □  □  □  ●  ○      （無）      □  ●  □        兩個框的邊界
                 ↑  ↑                    ↑
              綠現在 綠原位            紅現在
```

- **上軌**：每一節能不能按、配對一筆還是多筆。灰 = 不能按，藍 = 能按。**沒有第三種顏色，沒有空心，沒有虛線。**
- **下軌**：綠框與紅框現在在哪、原本在哪、可以搬去哪。高度是上軌的一半。
- 分岔處上軌局部裂成多線再合回來（捷運路線圖：幾種走法，殊途同歸），**不需要符號或圖例**。一側耗盡的分支畫成「（直接）」。
- 兩軌用 grid `auto-flow:column` 自動同欄對齊，欄寬由上軌撐開。

### 分岔撐高時的垂直對齊

pill 貼齊上軌**底部**、按鈕貼齊下軌**頂部**，兩者永遠只隔一個 `row-gap`——「哪顆按鈕屬於哪顆 pill」不需要靠眼睛拉一條長垂直線。

**分岔跨兩軌（`grid-row: span 2`），不是只佔上軌。** 只佔上軌的話，分岔多出來的高度 `E` 會全部灌進上軌，整叢 pill+按鈕被壓到容器下緣，分岔則浮在上方。跨兩軌之後 grid 把跨軌項目的多餘空間**平均分配**給兩條 `auto` 軌：

```
r1 = 24 + E/2        叢集 = [r1−24, r1+gap+12]
r2 = 12 + E/2        中心 = r1 − (24−gap−12)/2 = H/2
```

叢集中心恰好落在容器正中，與分岔的中心共線。實測 union 三分支：`H=105`、`r1=56`、`r2=44`，叢集中心 `52.5` = 容器中心 `52.5` = 分岔中心 `52.5`。

分岔因此**不需要下軌的佔位元素**。`.nostop` 只留給「有 pill 但該層不可停」這個罕見情形（實測五個 fixture 都沒發生），避免後面的欄錯位到下軌。

**上軌不再兼差表達「在不在查詢式裏」。** 舊版用虛線／透明／灰實心／綠字四種畫法擠在同一條軌道上，而虛線與 disabled 幾乎分不出來。現在邊界完全由下軌的綠實心與紅實心兩顆按鈕定義，上軌只需要回答「能不能按」。

## 4. 邊界：下軌按鈕

**不用拖曳。** 拖放對初學者不友善，而且拖曳強迫整條規格繞著它轉（版面凍結、落點不能被推走、不能坍縮、拖出捲軸就構不到）。改成一排可點擊的按鈕之後這些約束一次消失。

| 畫法 | 意思 |
|---|---|
| **綠實心** | 綠框現在在這一層（不可點） |
| **綠邊空心** | 綠框的原始位置 |
| **灰邊空心** | 點一下把框搬到這一層 |
| **紅實心** | 紅框現在在這一層（不可點） |
| **紅邊空心** | 紅框的原始位置 |

- **灰邊不區分綠紅。** §2 保證兩者可動範圍不重疊且首尾相接，所以每個灰按鈕的歸屬唯一：綠實心左邊的都是綠的、紅實心右邊的都是紅的。**位置本身就是答案**，再上色是重複編碼。
- 紅綠都只能往 ancestor（左）方向離開原始位置 ⇒ **空心的原位按鈕永遠在實心的現位按鈕右邊**；重合時只畫實心。
- 綠往左 = 抓更多筆（比對範圍擴到兄弟區塊）；紅往左 = 每筆抓更粗的單位。
- **一顆紅按鈕，所有紅框鎖步**，對齊基準是「從原始點擊處往上數」。

### 沒有停靠點的地方就留空

紅框只能停在「各紅框在該層標籤全部相同」的層（`validStops`）。實測下**洞只出現在分岔區** —— 綠側 `greenStrip` 給出 root→NCA 每一層、共同結尾各層依定義標籤相同，兩邊都是密的；分岔區各分支在那幾層的標籤本來就不一致，對不齊。

所以「只有可停層才有按鈕」跟「分歧點不放按鈕」是**同一條規則**，不需要第六種外觀。留空而不是畫一顆按不動的按鈕：**畫面上看得見的按鈕就是真的按得下去的按鈕。**

### 不做坍縮

邊界外的灰 pill **全部畫出來**，第 1 列超過寬度就橫向捲動。曾經做過「超過 N 層就摺疊」，但那與拖曳不相容（按下的瞬間摺疊層展開、落點從游標底下跑掉）。拖曳拿掉之後這條約束其實鬆了，但坍縮仍然不做 —— 它會讓下軌的欄位對應關係變成動態的，而下軌現在是唯一表達邊界的地方。

代價是第 1 列可能很長（綠框可一路往上到 `html`），所以每次重畫都要把綠實心～紅實心這一段捲回可視範圍。

**命中數對 pill 忠實，對邊界不忠實**：idx→bare 是單調放寬（數字不變 ⟺ 集合不變），但移動邊界不單調 —— 數字可能不動而命中的是完全不同一批元素。所以下軌按鈕的 hover 預覽同時搬動**頁面上的藍框**，不只改數字。

## 5. pill 規則

### 三態

| 狀態 | 條件 | 畫法 |
|---|---|---|
| **永久鎖** | 全 bare 基準下開關無差別 | 灰 |
| **坍縮但活著** | 全 bare 下有差、當前狀態下無差 | 灰，但會自己冒出來 |
| **可調** | 當前狀態下有差 | 藍 |

**推論：畫面上可點的 pill，點下去必然改變命中集合。** 不需要任何「這顆有影響」的標記。

### 永久鎖的判定（sound + complete）

**把其他所有開關設成 bare，在那個基準下比較這一顆的開與關。相同 ⇒ 永久無關。**

純 child 軸路徑下每個候選節點的祖先鏈唯一，所以

```
Result(σ) = C ∩ ⋂ⱼ Pⱼ(σⱼ)
```

各層條件獨立相交、不互相遮蔽。「第 k 顆永遠無關」⟺ `C ⊆ P_k(idx)`，而其他全 bare 時 `⋂_{j≠k} Pⱼ = 全集`，測到的正是這個條件。
Sound：全 bare 相同 ⇒ 任何 σ 下更小的交集也成立。Complete：全 bare 不同 ⇒ 存在反例。

成本 n+1 次 evaluate。**這條規則吃掉了 v2 的 `sibCount ≤ 1`**（只看兩個範例，嚴格較弱）→ 只需一條鎖定規則。

有效範圍是「當前紅綠邊界 + 當前分支集合」，每次 rebuild 重算。搬了邊界之後某顆 pill 從灰變藍，正好告訴使用者「你剛才那個動作讓這一層開始有意義了」。

**陷阱（v2 會踩、v3 不會）**：`div[1]` 底下 1 個 span、`div[2]` 底下 3 個。當前狀態下 `span[1]` 和 `span` 都回 1 筆，看起來可以鎖死；換到全 bare 基準立刻露出 2 vs 4。

### 預設值（結構規則，不用筆數規則）

| 節點 | 預設 | 理由 |
|---|---|---|
| 終端且**有直屬文字** | **idx** | 這是「欄位」，使用者點的位置就是證據 |
| 終端但**沒有直屬文字** | **bare** | 這是「一筆記錄」的容器，要抓到每一筆 |
| 其餘全部 | **bare** | 這些是容器，丟序號才會每一筆都抓到 |

終端是欄位還是記錄，判準是 **`noOwnText`（有沒有自己的直屬文字節點）**，不是「有沒有子元素」——
`<span>Unit test <b>是什麼</b></span>` 有子元素卻是文字欄位，這種富文字欄位（`<b>`／`<em>`／`<a>` 混在文字裏）在真實頁面非常普遍，用子元素當判準會全部誤判成容器。
跨範例的量詞取 **any**：只要有任何一個範例的終端有直屬文字就當欄位 —— idx 是比較緊的一邊，猜錯的後果是漏抓（看得見）。

**不採用「筆數比較多的那邊」**：那條規則在容器層對、在終端錯。兩個紅框都是 `span[2]`（第 2 個 span = 價格）時，翻成 bare 會把使用者最強的證據丟掉，換來一堆垃圾欄位。
差別在於：**尾端那一節是「抓哪個欄位」，上面每一節是「抓哪一筆」。**

預設值不依賴命中數 ⇒ **開關不會在使用者眼前自己翻面**。

### 上軌的視覺文法

只有兩種顏色。**灰 = 不能按，藍 = 能按。**

抽象模式（預設）—— 整顆 pill 就是那個方塊，講的是**基數**：

| 畫法 | 意思 |
|---|---|
| 灰實心方塊 | 不能按 |
| 藍實心方塊 + `1` | 配對一筆（有 predicate） |
| 藍實心方塊 + `*` | 配對多筆（無 predicate） |

標記模式 —— 講的是**字面查詢式**：

| 畫法 | 意思 |
|---|---|
| 整顆灰（含標記名） | 不能按 |
| 標記名 + 藍實心方塊，裏面是**實際序號** | 套用 predicate |
| 標記名 + 藍實心方塊**留空** | 移除 predicate |

兩個模式各自內部自洽：抽象講基數（`1` 與 `*` 在同一個語意軸上），標記講字面（`li` + `2` 逐字就是 `li[2]`，**畫面即查詢式**）。所以抽象模式方塊裏寫的是字面 `1` 而不是實際序號 —— 它回答的是「配對幾筆」，不是「第幾個」。

**移除 predicate 後方塊留空但同寬**（實測 18px → 18px）。切換鬆緊不該讓整列重排。

**刪掉的舊畫法**：空心塊、虛線空塊、綠字、四階灰。空心／虛線／實心三者在小尺寸下幾乎分不出來，而它們原本要表達的「在不在查詢式裏」已經由下軌回答。

不做「你改過這顆」的標示：沒有「回到預設」的操作，知道它被改過也做不了什麼；而藍色方塊的內容本來就看得見。

### 互動分工

- **點上軌藍方塊 = 切換鬆緊**（抽象模式整顆 pill 可按；標記模式按那顆藍方塊）
- **點下軌空心按鈕 = 搬邊界**。沒有第二種提交方式。
- **hover 兩軌都預覽**：hover 藍方塊 → 切換鬆緊後的命中集；hover 空心按鈕 → 搬過去之後的命中集。預覽是 v3 最有價值的機制，不能隨拖曳一起死掉 —— 而搬邊界正是最容易猜錯的動作，不該變成盲操作。
- **會亮的東西必須是能按的東西**：灰 pill 與實心（現位）按鈕都沒有 hover 效果，實心按鈕直接 `pointer-events:none`。

### 分岔段沒有特例

分岔線上的 pills 就是普通 pills，套同一套規則（預設 bare、無差別鎖掉、有差別可調）。
「一種 pill，一套規則」—— 若有些 pill 長得一樣卻不能點，使用者就得建立第二套心智模型。

## 6. 版面凍結

**pill 的「存在與否」只在提交時重算，預覽期間完全凍結。**

| 期間 | 會變 | 凍結 |
|---|---|---|
| hover 預覽（兩軌皆同） | 命中數、預覽列表、頁面藍框 | pills 與按鈕的存在／寬度／位置／顏色 |
| 點擊後 | 全部重算 | — |

拖曳拿掉之後這一節變得便宜很多：不再有「落點被推走」這個失敗模式，凍結只需要保證 hover 期間版面不動。

### 點擊後不得立刻反向預覽

點下去之後游標還停在原處，DOM 重建會讓瀏覽器對新元素**補送一次 `mouseenter`** —— 使用者會立刻看到一次方向相反的預覽。這是認知負荷最重的一種形式（「我剛按完，它為什麼又在示範相反的事？」）。

規則：**游標自上次點擊後必須移動過，hover 預覽才算數**。實作是一個 `moved` 旗標，任何點擊設 `false`，任何 `mousemove` 設回 `true`。效果等於「必須先離開再回來」。

## 7. 分岔（union 分支）

- **分支的身分是「形狀」（標籤序列），不是 tag+idx。** 否則 `li[1]` 與 `li[3]` 會併成兩條畫起來一模一樣的冗餘分支。序號相異時該層自然 `forced` bare —— 跟共同結尾的處理完全一致，不是特例。
- 分支上只有一個動作：**刪除（🗑，放在分支列左緣）**。不做「停用」—— 停用會讓有效範例掉到 1 個，破壞「至少選兩個」這條貫穿全工具的規則。
- 刪除會連同該分支綁的所有範例一起走，所以**刪到剩不足 2 個範例時垃圾桶失效**（灰掉）。
- **新增分支：分歧槽下緣的 ＋。這顆按鈕即使沒有分岔也必須在。** 「漏抓就再點一個範例」正是要在沒有分岔時把第一條岔路生出來；把 ＋ 藏在分岔裏會變成雞生蛋，等於廢掉 §1 選 union 的核心理由。沒有分岔時分歧槽不畫括號，只留 ＋。
- 一側耗盡的分支畫成「（直接）」。

## 8. 加範例

union 骨幹的失敗回復路徑就靠這個，是主線不是加分項。

1. `phase = 'add'`，只 push `examples`，**不動** `overrides`／綠框／紅框位置
2. `ncaOf` 是 N 元的
3. hover 預覽：點下去之前就看到「12 → 20 筆」
4. **二次確認的判準不是「共同結尾有沒有縮短」。** 還沒有分岔時，任何不同形狀的新範例都必然讓共同結尾縮短 —— 而那正是主要復原路徑。每次都跳確認等於把警告稀釋掉。真正該擋的是**會毀掉東西**：

   ```
   destructive ⟺ 紅框被迫移位（m.rUp ≠ G.rUp）
              或 使用者調過的某顆開關在新幾何裏不復存在
   ```

   什麼都還沒調就加變體 → 一次點擊完成；調了半天才加 → 才跳確認。
5. 移除紅框**不依賴 `G`** —— 配對失敗（`G === null`）正是最需要它的時候。overlay 是照 `examples` 畫的，不經過 `G`（見 §11）。

## 9. 預覽列表

Panel 下方一列一筆，只顯示前 N 筆（`LIST_N = 12`），不捲動。

### diff 以「抽取結果」為基底，不是以節點身分

拿 DOM 節點做 Set 比對會產生假變化：紅框從 `span` 移到它的 `a`，8 個元素全換、但每一列文字一模一樣 → 畫面上 8 刪 8 增。**列表是抽取結果的預覽，就該用抽取結果來 diff。**

- 用 `getTxt(el)`（已 normalize + trim）當 key，重複文字走**多重集**計數比對
- 兩邊文字序列完全相同時顯示「共 N 筆 · **無變化**」，**不顯示箭頭** —— 「這個動作不改變你抽到的東西」本身就是使用者最想知道的答案

| 狀態 | 畫法 |
|---|---|
| 目前命中 | 正常列 |
| 預覽會新增 | 藍底 |
| 預覽會消失 | 淡化 + 刪除線，**位置保留不重排** |
| 你選的範例 | 左緣紅色細條 |
| 無文字 | 顯示 `(空)` |

每列：**◎（捲到該元素）+ 序號 + 文字**。捲頁掛在 ◎ 上，不掛整列 —— 整列可按會讓它宣稱自己是控制項。**列本身沒有 hover 效果。**

底部一行寫成「共 12 筆 → 18 筆」而不只是「18」—— 新增的列可能全在前 N 之外。

## 10. 面板數字

**整個面板只留一個數字**：底部的「命中 N 筆」。hover 上軌藍方塊或下軌空心按鈕時就地變成預覽值。

v2 在每顆開關兩端、分歧開關、chips 上都掛命中數，一個中等複雜的查詢式會有十幾個數字在競爭注意力，而且大多數時候都一樣。資訊量沒損失（一次只 hover 一個東西），畫面從十幾個數字降到一個。

## 11. 框線

`*{box-sizing:border-box}`，2px border 畫在框內，所以 `pad` ≠ offset。

| 框 | 語意 | 實作 |
|---|---|---|
| 綠 | 完全在外 | `p = +3` |
| 藍 | 騎在邊框上 | `p = +1` |
| 紅 | 在裏面 | `p = 0` + `background: rgba(red,.10)`，**不畫 border**；`pointer-events:auto` + `cursor:not-allowed`，自己就是移除按鈕 |

三者是**三種不同的編碼**（外環／邊線／填色）而非三個同心環：範例元素同時也是命中元素，同心環會變成相距 2px 的平行線，看起來像算圖瑕疵；而填色在任何尺寸下都成立。

### 紅框 overlay 自己就是移除按鈕

**左鍵點紅框 = 移除那個範例**，游標 `not-allowed`。沒有右鍵手勢。

把 overlay 變成點擊目標（`pointer-events:auto`，索引寫在 `dataset.gpex`）是**唯一能穩定控制游標的方式**：把 `cursor` 設在頁面元素上會被它自己的樣式蓋過，而紅框多半就是 `<a>`，`a{cursor:pointer}` 直接贏。

順帶補掉一個洞：`swallow` 與 `onClick` 都只在 `picking()` 時作用，所以**調校階段左鍵點在紅框上，若那是連結會直接導航離開**。overlay 吃掉點擊之後就不會了。

三個必須跟著改的地方：

- 選擇器要寫成 `#gp-overlay .bx.red`，否則吃不贏 `#gp-overlay .bx{pointer-events:none}` 的 (1,1,0)
- `onClick` 必須在 `UI(e.target)` **之前**特判 —— overlay 住在 `#gp-overlay` 裏，`UI()` 會把它當成工具自己的介面而放行給頁面
- select／add 階段 `onMove` 經過紅框時 `hoverEl` 變 `null`（橘框消失）。這是對的：巢狀元素本來就不能當範例，原本會吐 toast「與現有範例巢狀」，現在直接變成「移除它」

**不做二次確認。** 移除到剩不足 2 個範例時會連 `overrides`／`redUp`／`greenUp` 一起清掉，但每次都跳確認等於把警告稀釋掉（同 §8）；而範例本身重點一次就回來了。

### 畫布永遠只畫「一個狀態」

有預覽時藍框就是**預覽後**的集合，實線，直接搬過去；沒預覽時就是當前集合。**畫布從不畫兩個狀態的差** —— 虛線代表增刪是一整套要學的視覺語言，認知負荷最高，不該是預設。增刪的差只活在下方列表。

視覺語言的認知負荷分級（由低到高）：

1. hover 元件有視覺變化 = 這東西可以按
2. hover 觸發預覽（需先離開才能再觸發）／ 預覽顯示在列表
3. hover 觸發預覽，且點擊後立刻反向觸發
4. 畫布上用虛線表示增刪

v3 停在 2。3 用 `moved` 旗標擋掉，4 不做（未來可當進階選項）。

## 12. 輸出

**一條字串**，不是 v2 的兩行（`綠框: …` + `判斷式: …`，使用者得自己接）。

**畫面即輸出，沒有第二種表達式。** 不做「嚴謹式」：它只是換一種無聲失敗（寬鬆式改版後多抓垃圾；嚴謹式改版後序號整排位移抓到錯的東西），不值得多一條要維護的路徑和「複製出來的跟看到的不一樣」的認知落差。

**已知代價**：v3 只能產出對當前頁面的最小式，無法手動加上「今天不划算、明天才擋得住雜訊」的 predicate。接受。

### 錨點

複製輸出真正的弱點不是 predicate，是綠框錨點。v2 的 `absPath` 每層都帶序號（`/html[1]/body[1]/div[3]/main[1]`），頁首多一個 banner 整條就報廢 —— 在錨點還是全序號絕對路徑的前提下爭論 predicate 嚴謹度是優化錯的那一端。

優先序：綠框或最近祖先有 `id` → `//*[@id="x"]/…`；否則夠獨特的 class → `//*[contains(@class,"y")]/…`；都沒有才退回全序號絕對路徑。（`label()` 已在算 id/class，資料現成。）

**錨點不做成可調** —— 它沒有「多抓少抓」的連續光譜可以預覽，做成互動元件既無 hover 預覽可搭，也違背極簡目標。複製後的 toast 把整條字串秀出來讓人看一眼即可。

## 13. 不變量與可刪除的東西

**命中數永遠 ≥ 範例數。** 兩個紅框在任何可達狀態下都被自己那條分支命中：序號相異時 `forced` 強制 bare，序號相同時 idx 也中。
→ 查詢式求值本身不會回 0。

但有兩種**幾何／定址**失敗仍然可達，而且必須出聲，否則使用者只看到空面板：

| 狀態 | 條件 | 訊息 |
|---|---|---|
| 幾何失敗 | `validStops` 為空 —— 這些元素在任何一層都對不齊 | 「無法建立查詢式 — 右鍵紅框可移除重選」 |
| 定址失敗 | `matched.length < examples.length` —— 打破上面那條不變量 | 「有元素無法用 XPath 定址（多半是 SVG 內部）」 |

### SVG 不可用標籤名定址

實測：`./span/svg` 回 **0 筆**。SVG 元素在 SVG 命名空間，XPath 1.0 的無前綴 name test 匹配不到（`./span/*` 和 `local-name()` 才行）。

所以**選取一律夾到包住 svg 的那個 HTML 元素**（`pickable()`），並額外擋掉任何不在 XHTML 命名空間的元素（`<foreignObject>` 之類）。要真的支援抓 icon，得讓查詢式長出 `*[local-name()="svg"]`，那會同時污染表達式與抽象模式的 pills —— 等真的需要再說。

**每個動作都是自己的反函數。** 下軌按回原位（原位永遠畫著綠邊／紅邊空心，看得見）、上軌藍方塊再點一次、分支再啟用一次，全部完全還原。唯一例外是破壞性的第三範例 —— 而那正是唯一放了二次確認的地方。
→ **v3 不需要 undo 系統。**

**v3 相對 v2 刪掉的**：`//` 開關、`skipDiverge`、子輪廓 chips (`shapeOn` / `childTags` / `matchesIfChip`)、`noQuery` 狀態、「為何」欄、每顆開關的命中數 (`.n`)、無文字警告文字、無命中錯誤態、由上往下的表格版面。

## 15. 2D 擷取：欄位展開

1D 決定「抓哪些東西」，2D 決定「那一列有哪些欄」。**藍框集合完全不變，一筆記錄仍然輸出一列。** 不引入巢狀作用域、不需要 breadcrumb、不產生 1:N 展開。

`field-extraction-design.md` 訂了三條路線（UI mode／script mode／copy-raw）。**v3 只做 UI mode**，並且用一套三分類取代 v2 的巢狀樹加坍縮演算法。

工具列：現有「擷取」改名 **`[1D 擷取]`**，右側加 **`[2D 擷取…]`**。

### 三分類

| 類別 | 定義 | 範例 |
|---|---|---|
| 第一類 | 肉眼可見，沒有巢狀夾層元素 | `<div>26:30</div>`、`<span>310K</span>`、`<div><div>15h ago</div></div>` |
| 第二類 | 肉眼可見，有巢狀夾層元素 | `duration <div>26:30</div> or so`、`<div>from <div>15h ago</div> to...</div>` |
| 第三類 | 肉眼不可見 | `<a href="/watch?v=…">`、`<div class="hidden">hidden message</div>` |

展示順序 **orderby 類別 thenby 文件順序**。三類都不顯示 tagName —— 標籤名對「這格是什麼資料」沒有解釋力，值預覽才有。

### 切分規則

```
對紅框子樹裏的每個元素 E：
  E 有非空白直屬文字 → E 是欄位，停止下探
      子樹裏還有帶文字的元素 → 第二類（blob）
      否則                     → 第一類
  E 無直屬文字 → 容器，遞迴進子節點
```

「非空白文字節點存在於兩個連續 open tag 之間或兩個連續 closing tag 之間」的等價形式，亦即 **mixed content**。`</div>xxx<div>`（前一個結束、後一個開始）同樣成立 —— 判準是元素有沒有直屬文字，不是列舉標籤的排列。

### 不需要坍縮

v2 要坍縮（只有一個子節點的節點與其子節點合併，標籤以 `/` 相接）是因為它把整棵樹畫出來。v3 的遞迴只在「有直屬文字」處產出一列，容器天生不出現在畫面上：`<div><div>15h ago</div></div>` 直接得到一列 `15h ago`，沒有 `div/div` 這種需要解釋的合併標籤。

v2 三條剪枝規則的下場：**A**（移除空白 text node）保留；**B**（移除沒有存活子葉的元素）被遞迴本身吸收；**C**（移除有文字但不可見的元素，預設開）**被第三類取代** —— v2 是真的刪掉，v3 只是排到最後一區，東西還在、還能勾。

### 富文字算夾層

`<span>Unit test <b>是什麼</b></span>` 是第二類。**只看結構，不看標籤名，沒有 `b`/`em`/`strong` 白名單。**

白名單很誘人（google fixture 每一筆標題都長這樣），但同一條規則會讓 `<div>from <b>15h ago</b> to</div>` 塌成一行 `from 15h ago to`，`15h ago` 就再也挑不出來 —— 而那正是案例一的結構，只是標籤從 `<div>` 換成 `<b>`。而且白名單在網站用 `<span class="bold">` 而不用 `<b>` 時就失效了。

代價是富文字標題多一層縮排。常見情況直接勾 `*` 就是整個標題一欄，多一次點擊；換來的是隨時可以改挑其中一片。

### 第二類：blob

`*` = **blob 根**，即第一類／第二類判定分岔的那個元素。與紅框的根無關。

攤平 = 從 `*` 起 DFS，依文件順序吐出：

- 非空白 text node
- **沒有元素子節點**的元素（取 `innerText`）
- 有元素子節點的元素繼續下探，它自己的直屬文字照樣在原位吐出

**永遠兩層**（`*` + 葉），而且 **blob 不會巢狀** —— 切分規則一碰到有直屬文字的元素就停止下探並整包攤平，`*` 底下不可能再有 `*`。

四個形狀不同的輸入得到同一個攤平結果：

```
<div>from <div>15h ago</div> to...</div>
<div>from <span><span>15h ago</span></span> to...</div>
<div><span>from <span>15h ago</span></span> to...</div>
<div>from <span><span>15h ago</span>to...</span></div>
```
```
- [ ] *
  - [ ] from
  - [ ] 15h ago
  - [ ] to...
```

中間層不長 `*`：同一 blob 內勾選的葉子本來就會併成一欄，中間層的 `*` 不提供任何新能力，只多一層要看的東西。

### 第三類

屬性白名單 **`href`／`src`／`title`／`datetime`**。不含 `data-*` —— 現代框架會噴出大量 `data-testid`／`data-state`／`data-radix-*`，樹會被淹沒。

不可見判定 `el.getClientRects().length === 0`：

- **抓得到**：`display:none`（含整棵子樹）、零尺寸、未掛載
- **抓不到**：`visibility:hidden`、`clip-path`／`left:-9999px` 這類 sr-only

抓不到的**刻意留下**。sr-only 正是「人眼看不到但語意精確」的資料（相對時間旁邊的絕對時間戳）。在三分法下這只影響排序、不會掉資料，賭注遠低於 v2 —— v2 的規則 C 是預設把它們刪掉。

**隱藏文字與屬性一律抽到第三類，不留在 blob 裏。** `*` 取 `innerText`，而 `innerText` 不含 `display:none` 的文字 —— 留在 blob 裏會讓「`*` 必然含蓋所有葉」這條互斥依據破掉。抽出來則等式精確成立，而且 blob 中間夾一個隱藏時間戳，本來就該是獨立一欄。屬性同理：屬性在文字流裏沒有位置，塞進空白 join 只會污染那一欄。

### 常數欄位自動移除

**取樣範圍內每一列的值都一樣 ⇒ 那是樣板字不是資料，從清單移除。** 典型是 `title="播放這部影片"`、`href="#"` 這種每張卡都一樣的東西。

**只套第一類與第三類，不套第二類。** blob 裏的樣板字（`from` / `to now`）是它存在的一部分 —— `*` 取的就是含樣板字的整串，把葉子砍掉會讓 `*` 與葉子的關係說不通。另一個理由是成本：判定要對每一列求值，第一類要讀 `innerText`（觸發 layout），blob 的葉子數量遠多於第一三類。

判定與 coverage **合成同一趟**（`covOf(xp, withVal)`），不多跑一次 `evaluate`。

**常數與 coverage 是獨立的兩件事。** deco fixture 的 `href="#"` 在 union 分支下 3 筆抓不到、1 筆是 `#` —— 值不同（`''` vs `'#'`）所以不算常數，而 `1/4` 的琥珀徽章正確地說出了真正的問題。反過來 clean fixture 的 `href="#"` 四筆全中且全同，就該被藏起來。

### 留一條可展開的記錄

樹頂一行「› 已隱藏 N 項所有列都相同的內容」，點一下展開，展開後那些列標成灰斜體。

自動移除的失敗方向是**靜默隱藏資料** —— 變化只出現在取樣 50 筆之後的欄位會被誤殺，而使用者完全看不到。一行字加一次點擊，就把誤殺的代價從「永遠拿不到」降到「多一次點擊」，也因此**不需要設筆數門檻**（只有 2 筆時巧合相同的機率高，但那時列表本來就短，展開看一眼很便宜）。

**已勾選的常數列一律不藏。** 展開 → 勾選 → 收合，若把它藏起來就會出現一欄看不見卻仍在輸出裏。所以隱藏條件是 `konst && !showConst && !checked`；全部常數列都被勾選時那一行提示也跟著消失，因為確實什麼都沒藏。

### 啟用條件不套這個過濾

`can2d` 仍然用**未過濾**的結構計數。兩個理由：

1. 過濾要對每一列求值，而 `can2d` 跑在每一次 `rebuild()`（切 pill、搬邊界）—— `innerText` 的 layout 成本不值得。
2. **更重要的是這樣才對。** clean fixture 的卡片過濾後只剩 1 列，若用過濾後的數字就會 disable，使用者連展開拿回 `href` 的機會都沒有。開著而 modal 裏只有一列加一行說明，比直接鎖死好。

### 欄位模型：一欄 = 一個列群組

列群組只有三種：**第一類項**、**第二類 blob**、**第三類項**。

- 第一類／第三類：勾選即一欄，一項一欄，沒有合併。
- 第二類：同一 blob 內勾選的葉子以**空白**相接。

**沒有「整列」列。** 卡片的根 div 沒有直屬文字 → 它是容器 → 從不出現在任何一區。要整列 innerText 就關掉 modal 用 1D 擷取。v2 有一個 root 列且與所有子孫雙向互斥，v3 不做 —— 少一個特例、少一條互斥規則。

### 切點：blob 內的分欄

v2 把斷點趕出樹、另闢一條分欄尺，理由是「樹是二維而斷點只存在於一維序列，已勾選的項目在畫面上通常不相鄰」。**v3 的 blob 已經被攤平成兩層，葉子本身就是一維且相鄰**，那個理由消失，斷點回到樹裏。

但葉子可以不連續勾選（勾 1 跟 3、跳過 2），此時「1 跟 3 之間」的縫隙被未勾選的第 2 列擋住。所以斷點**不是點縫隙**，而是每個已勾選葉子帶一個「從這裏開新欄」的旗標：

```
- [ ] *
  ┃[x] Alice ·        ①
  ┃[x] 2h ago         ②   ← 點切點記號開新欄
  ┆[x] · 12 replies   ②   ← 虛線 = 沒斷，併入前一欄

→  Alice ·  ⟨tab⟩  2h ago · 12 replies
```

第一個已勾選葉子的旗標鎖死為開欄。**欄號由前綴和推導，不是每一項的自由變數** —— 合法集合（文件順序下從 1 開始、非遞減、每次最多 +1）與「切成 g 段連續區間」一一對應，真正的自由變數是切點位置，**任何操作序列都不可能產生非法狀態**，不需要驗證邏輯。取消勾選時該葉的切點旗標一併消失，後面的欄併回前一欄並重新編號。

**分欄是第二類專屬**，第一類與第三類永遠一項一欄。

### 互斥

**只在單一 blob 內部**：`*` ↔ 它自己的葉子，雙向 disable。`*` 的 `innerText` 必然含蓋所有葉，並存必然重複；雙向 disable 讓使用者從任一端都看得出互斥，不會以為工具壞了。

第一類 ↔ 第二類、不同 blob 之間、跨類 —— **全部獨立，不互斥**。

### 欄序

**輸出欄序 = 畫面順序**（類別 → 文件順序）。畫面上從上往下讀到的順序就是貼上去的左右欄序，沒有隱形映射，與 §5「畫面即查詢式」同一條原則。

代價：`href` 永遠排到最後，即使它在文件順序上最前面。接受 —— 另一個選項（照文件順序）會讓畫面的上下順序跟輸出的左右順序不一致，使用者得在腦裏做一次重排才能預測結果。

### 樣本紅框

樹只從**一個**樣本紅框長出。不做跨列聯集 —— 聯集出來的樹不對應畫面上任何一個實際元素，選擇式出錯時無從推理。

modal 頂端一列樣本切換器 `[紅1] [紅2] [紅3]`，**預設最後點擊的那個**。切換 = 重建樹 + **清空勾選**，不嘗試用路徑字串把舊勾選比對回新樹（換了樣本意味著結構可能完全不同，勉強對回去只會產生看似成功實則錯位的選擇）。

有切換器，是因為「樣本缺某個欄位」這個方向的問題 **coverage 徽章偵測不到** —— 別的列有、樣本沒有時，那個欄位在樹上根本不存在。v2 的解法是「關掉、右鍵刪紅框、重點」，修復路徑太長且不顯著。

### 回饋：兩層，管不同的時機

**coverage 徽章（選之前）** 掛在**每一列**上，含第二類的 `*` 與它的每一片葉子。葉子才是真正會序號位移的那一層（`text()[2]` 在別的列可能不存在），只掛 `*` 恰好蓋住最脆弱的地方。

| 情況 | 徽章 | 該列輸出 |
|---|---|---|
| 全部列命中 1 個 | `14/14` 綠 | 值 |
| 部分列命中 0 個 | `9/14` 琥珀 | 空字串 |
| 任一列命中 > 1 個 | `14/14⚠` 橘 | 多值以空白 join |

⚠ 不阻擋複製，只提醒。

取樣**前 50 筆**，無可調參數。`matched > 50` 時樹頂顯示「診斷以前 50 筆取樣（共 1,203 筆）；擷取仍為全部」，徽章分母寫 `50` 而非 `1203`，與那行說明互相印證。成本上界因此鎖死在 leaf 數 × 50；未取樣時 100 個 leaf × 1000 筆 = 十萬次 `document.evaluate`，主執行緒會卡死數秒，而那正是這工具最有價值的場合（捲了很久的無限捲動清單）。**擷取本身永遠跑全部。**

**底部預覽表（選之後）**：前 10 筆 × 已勾選欄。徽章說「這條路徑在幾列上成立」，預覽表說「抓到的內容對不對」—— 前者診斷不出「路徑命中了，但抓到的是別的字」，後者診斷不出「為什麼是這一欄壞掉」。兩者不可互相取代。

### 取值與輸出

| leaf | 取值 |
|---|---|
| text node | `textContent` |
| 無元素子節點的元素 | `innerText` |
| blob 的 `*` | `innerText` |
| 屬性 | 屬性原始值 |

一律再過現有的 `norm()`（`\s+` → 單一空白）。

**不做 Control Pictures 逃逸。** v2 那整套分析（引導字元、`C:\new\table`、`&amp;`）是為了**保留**換行資訊而存在的；v3 的 1D 早就用 `norm()` 把換行與 tab 正規化掉了，而 `\t` 與 `\n` 是唯二會炸掉 TSV 的字元，兩個都在 `\s` 裏。2D 另搞一套只會讓 1D 與 2D 對同一筆資料給出不同結果。

分隔：欄內多來源 → 空白；欄之間 → `\t`；記錄之間 → `\n`。**不輸出標題列** —— 唯一可用的欄名是選擇式字串，那是雜訊不是欄名。

- **0 命中輸出空字串，不跳過該列** —— TSV 每行 tab 數必須固定，缺值必須佔位。
- **N 命中以空白 join，不取第一個** —— 取第一個會靜默丟資料；join 之後那格異常地長，預覽一眼看得出不對。與「同一 blob 內多個葉子以空白相接」是同一條規則。

### 狀態生命週期：關掉即丟

**欄位定義只活在 modal 開啟期間。**

modal foot 是唯一出口：`[複製 14 筆 · 4 欄]`。主面板的「1D 擷取」永遠是單欄 `innerText`，`文字／直屬／標記` 三態開關照常作用於 1D。

代價：關掉 modal 去調任何 1D 的東西再回來，勾選與切點全部重來 —— 包含那種根本沒動到樹的 pill 微調。**換來的是整條失效規則消失**：不需要「欄位什麼時候該消失」的判斷、不需要 `sampleEl` 身分比對、不需要「樣本已變更，欄位選擇已重置」的提示。唯一的重建時機是 modal 內切換樣本。

### 觸發條件

```
enable ⟺ classify(樣本紅框) 的列數 ≥ 2
列數 = 第一類數 + 第三類數 + Σ（每個 blob 的葉數）
```

blob 的葉數至少為 2（只有一片葉就不是 mixed content），所以任何一個 blob 都足以啟用。`<span>310K</span>` 只有 1 列 → disable；`<a href="/x">worth it</a>` 有 2 列（文字 + href）→ enable。

**這不是 `field-extraction-design.md` 警告的那種預判。** 那份文件說「不做任何有沒有東西可抓的預判」，理由是用 `txt()` 與 `textContent` 比較這種 **proxy** 會產生假陰性，而假陰性的方向是靜默隱藏資料。v3 沒有 proxy —— 直接跑真正的分類器，算出 0 或 1 列就代表 modal 打開也真的沒東西可分。而且那條規則主要是為了保護 copy-raw 分頁（「解析不出東西時最有價值」），v3 不做 raw mode，理由基礎消失。

成本只有樣本紅框那一顆元素的子樹，跑不掉。disable 時 tooltip 說明原因，不靜默。

### 容器：`<dialog>` + `showModal()`

Top layer，不吃 z-index 競賽 —— 現有面板靠 `z-index:2147483200` 硬頂，任何後插入且同樣開到最大值的頁面元素都會贏過它。原生 `inert`、原生 Esc 與焦點鎖。

兩行守衛（`<dialog>` 蓋不掉的）：

```js
// onMove：::backdrop 是虛擬元素不會被回傳，elementFromPoint 可能仍回傳底下的
//         inert 頁面元素，橘框會繼續跟著游標跑（各家瀏覽器對 inert 與 hit test 不一致）
if (dlg.open) return;
// keydown：掛在 window capture 階段，會早於 dialog 的 cancel 事件，直接把整個工具 off 掉
if (dlg.open) return;
```

**Esc 分兩層**：modal 開著時第一次只關 modal，第二次才結束工具。誤按一下就把整個標註狀態連同工具炸掉，是不合比例的懲罰。

代價：backdrop 連工具列一起蓋住並使其 inert，modal 開啟期間不能點 pill。可接受 —— 樣本切換器已在 modal 內，而且欄位狀態本來就不跨 modal 存活。

樣式需要與現有 button/span 上 `all:unset` 同等級的顯式覆寫（頁面 reset 常命中 `dialog` 與 `::backdrop`），但**不能用 `all:unset`** —— 那會破壞 top layer 定位。
