# generic-parser v3 沙盒 — 設計規格

v2 的路線是「盡量在 UI 上把話說完」。v3 反過來：**把解釋變成看得見的狀態，然後把解釋刪掉。**

一條總原則：**保留指令，刪除解釋。**「你現在該做什麼」留在畫面上；「為什麼會這樣」一律由視覺承擔，不寫字。

平台：**桌機 only**。hover 預覽是 v3 最有價值的機制，不為手機犧牲它。

---

## 1. 演算法：union 骨幹，沒有 descendant search

分歧點一律用 union 處理，`//` 與 extra predicate **在 v3 完全不存在**。

```
(./chainA | ./chainB)/共同結尾
```

XPath 1.0 限制（已實測）：`(A|B)/suffix` 合法，`a/(b|c)` 不合法 —— **括號必須提到最左**。
一側耗盡時該分支寫成 `.`（`(./aside/div | .)/div/span[2]` 可跑）。

**為什麼是 union 不是 descendant：**

1. union 只用使用者真的給過的證據；descendant 是工具替他發明一個沒看過的推論，再發明 predicate 補救。
2. union 的失敗是**漏抓**（藍框少了，看得見，修法是再點一個範例）；descendant 的失敗是**誤抓**（垃圾混在結果裏，看不見）。寧可漏抓。
3. 砍掉 descendant 就砍掉整棵 extra predicate 的決策子樹。
4. union 天然支援 N≥3：「漏了就再加一個範例」。

**代價與補救**：頁面有多種巢狀變體時，使用者不知道自己漏了什麼。內部跑一支 `.//共同結尾` 探針比對命中集合，多出來的就提示「還有 N 筆長得不太一樣」，點下去**從那 N 筆裏挑一個當第三個範例、長出第三條分支**（不是切換成 descendant）。
噪音防護：只在 `多出來筆數 ≤ 目前命中數` 時才顯示。**此項優先度低，可延後評估。**

## 2. 幾何

```
綠框 ─────────── NCA ═══分岔═══ 共同結尾 ─────── 紅框 ─── 原始點擊處
     兩路徑完全共用        兩條         形狀共用
```

- 綠框 = 求值的根，**不在查詢式裏**（`chain = segsUp(nca, green)` 不含 green）→ 邊界落在綠框 pill 的**右側縫隙**
- 紅框 = `tail` 的最後一段，是被命中的東西本身 → 邊界落在紅框 pill 的**右側縫隙**
- NCA 由範例決定，紅框在自己子樹內移動時 **NCA 不變**，是線上的固定樞紐
- 綠框可動範圍 `[root, NCA]`、紅框 `[分岔對齊層, 原始點擊處]`，兩者不重疊且首尾相接 → **它們在同一條線上**

## 3. 版面：一列鐵路圖

不是三列。是**一列，在分岔處局部裂成兩線再合回來**。

```
                        ┌ aside  div ┐
 ⋯4層⋯  main  ul │ li ──┤            ├── span[2] │  em ⋯
                 ▲                            ▲
                 綠拉桿                        紅拉桿
```

- 捷運路線圖的直覺：兩種走法，殊途同歸。**不需要符號或圖例。**
- 括號內 = 查詢式。左右兩側（綠框以上、紅框以下）的 pills **灰掉**並摺成「⋯ N 層」。
  → 「無法調節的節點自動坍縮」不需要另一套規則：**在不在邊界內就是規則。**
- 一側耗盡的分支畫成一條空直線（「這條路什麼都不用走」）。

## 4. 邊界標記

**▼ = 現在（可拖）；▽ = 原始位置。標記指著「哪一顆 pill」，不是指著縫隙。**

嚴格說邊界確實落在縫隙上（綠框是求值的根、不在查詢式裏），但縫隙上的直立拉桿在畫面上會讓人分不清它屬於左邊還是右邊那一層 —— 這個疑慮的代價高過幾何上的精確。

- ▼ 掛在綠框／紅框當前那顆 pill 上方；▽ 掛在原始位置那顆 pill 上方
- 紅綠都**只能往 ancestor（左）方向離開原始位置** ⇒ **▽ 永遠在 ▼ 的右邊**；重合時只畫 ▼
- 綠往左 = 抓更多筆（比對範圍擴到兄弟區塊）；紅往左 = 每筆抓更粗的單位
- **一顆紅 ▼，所有紅框鎖步**，對齊基準是「從原始點擊處往上數」
- 分岔區內**只能停在兩側標籤對得齊的層**，對不齊的跳過
  → 紅 ▼ 往左拖進分岔區停在對齊層，路徑就對稱了，**岔路當場併回單線**
- **按下不重畫任何東西。** 從按下到放開，版面必須完全凍結。

### 不做坍縮

邊界外的灰 pill **全部畫出來**，第 1 列超過寬度就橫向捲動。曾經做過「超過 N 層就摺疊」，但那與拖曳不相容：按下 ▼ 的瞬間摺疊層展開，整列往右推，**▼ 從游標底下跑掉**。摺疊帶來的視覺節制，抵不過破壞主要操作的代價。

代價是第 1 列可能很長（綠框可一路往上到 `html`），所以每次重畫都要把 ▼g～▼r 這一段捲回可視範圍。拖曳中若落點在捲軸外就構不到 —— 目前接受「先捲再拖」，沒做邊緣自動捲動。

**命中數對 pill 忠實，對邊界不忠實**：idx→bare 是單調放寬（數字不變 ⟺ 集合不變），但移動邊界不單調 —— 數字可能不動而命中的是完全不同一批元素。所以拖曳靠**頁面上藍框的即時搬移**傳達。

## 5. pill 規則

### 三態

| 狀態 | 條件 | 畫法 |
|---|---|---|
| **永久鎖** | 全 bare 基準下開關無差別 | 不畫序號片 |
| **坍縮但活著** | 全 bare 下有差、當前狀態下無差 | 不畫，但會自己冒出來 |
| **可調** | 當前狀態下有差 | 畫序號片 |

**推論：畫面上可點的 pill，點下去必然改變命中集合。** 不需要任何「這顆有影響」的標記。

### 永久鎖的判定（sound + complete）

**把其他所有開關設成 bare，在那個基準下比較這一顆的開與關。相同 ⇒ 永久無關。**

純 child 軸路徑下每個候選節點的祖先鏈唯一，所以

```
Result(σ) = C ∩ ⋂ⱼ Pⱼ(σⱼ)
```

各層條件獨立相交、不互相遮蔽。「第 k 顆永遠無關」⟺ `C ⊆ P_k(idx)`，而其他全 bare 時 `⋂_{j≠k} Pⱼ = 全集`，測到的正是這個條件。
Sound：全 bare 相同 ⇒ 任何 σ 下更小的交集也成立。Complete：全 bare 不同 ⇒ 存在反例。

成本 n+1 次 evaluate。**這條規則吃掉了 v2 的 `sibCount ≤ 1`**（只看兩個範例，嚴格較弱）→ 只需一條鎖定規則。

有效範圍是「當前紅綠邊界 + 當前分支集合」，每次 rebuild 重算。拖了拉桿之後某顆 pill 解鎖冒出來，正好告訴使用者「你剛才那個動作讓這一層開始有意義了」。

**陷阱（v2 會踩、v3 不會）**：`div[1]` 底下 1 個 span、`div[2]` 底下 3 個。當前狀態下 `span[1]` 和 `span` 都回 1 筆，看起來可以鎖死；換到全 bare 基準立刻露出 2 vs 4。

### 預設值（結構規則，不用筆數規則）

| 節點 | 預設 | 理由 |
|---|---|---|
| 終端且**有直屬文字** | **idx** | 這是「欄位」，使用者點的位置就是證據 |
| 終端但**沒有直屬文字** | **bare** | 這是「一筆記錄」的容器，要抓到每一筆 |
| 其餘全部 | **bare** | 這些是容器，丟序號才會每一筆都抓到 |

終端是欄位還是記錄，判準是 **`noOwnText`（有沒有自己的直屬文字節點）**，不是「有沒有子元素」——
`<span>Unit test <b>是什麼</b></span>` 有子元素卻是文字欄位，這種富文字欄位（`<b>`／`<em>`／`<a>` 混在文字裏）在真實頁面非常普遍，用子元素當判準會全部誤判成容器。
跨範例的量詞取 **any**：只要有任何一個範例的終端有直屬文字就當欄位 —— idx 是比較緊的一邊，猜錯的後果是漏抓（看得見）。

**不採用「筆數比較多的那邊」**：那條規則在容器層對、在終端錯。兩個紅框都是 `span[2]`（第 2 個 span = 價格）時，翻成 bare 會把使用者最強的證據丟掉，換來一堆垃圾欄位。
差別在於：**尾端那一節是「抓哪個欄位」，上面每一節是「抓哪一筆」。**

預設值不依賴命中數 ⇒ **開關不會在使用者眼前自己翻面**。

### 視覺文法

| 樣子 | 意思 |
|---|---|
| `div` `[1]` 序號片**實心** | 序號開著 |
| `div` `[1]` 序號片**空心描邊** | 序號關著，可點開 |
| `div`（無序號片） | 永久鎖，不可調不佔位 |

**畫面即查詢式**：實心 `[1]` 就是查詢式裏真的有 `[1]`，不需要翻譯。灰掉的 pill 一律不顯示序號片。

### 抽象化開關（預設開）

預設隱藏所有標記名與序號字面，**整顆 pill 就是開關本身**：

| 抽象化畫法 | 意思 |
|---|---|
| 灰底實心塊 | 永久鎖，不能按 |
| 藍色實心塊 | 序號開著 |
| 藍色空心塊 | 序號關著，可點開 |
| 虛線空塊 | 灰掉（不在查詢式內） |

需要看標記名時按「標記」切回具名模式（`div` + `[1]` 序號片）。

不做「你改過這顆」的標示：沒有「回到預設」的操作，知道它被改過也做不了什麼；而 on/off 本來就看得見。

### 互動分工

- **click pill = 切換序號**（抽象化模式下整顆 pill 可按；具名模式下按序號片）
- **拖 ▼ = 唯一的邊界提交方式**
- **hover 不做預覽。** 預覽只發生在拖曳過程中。
- **會亮的東西必須是能按的東西**：沒有開關的 pill 一律沒有 hover 效果。

### 分岔段沒有特例

分岔線上的 pills 就是普通 pills，套同一套規則（預設 bare、無差別鎖掉、有差別可調）。
「一種 pill，一套規則」—— 若有些 pill 長得一樣卻不能點，使用者就得建立第二套心智模型。

## 6. 版面凍結

**pill 的「存在與否」只在提交時重算，預覽期間完全凍結。**

| 期間 | 會變 | 凍結 |
|---|---|---|
| 拖曳中 | 頁面藍框、命中數、預覽列表、▼ 的位置、pills 的灰／不灰 | pills 的存在／寬度／位置 |
| hover 預覽 | 命中數、預覽列表、頁面藍框 | 同上 |
| 放開／點擊後 | 全部重算 | — |

### 點擊後不得立刻反向預覽

點下去之後游標還停在原處，DOM 重建會讓瀏覽器對新元素**補送一次 `mouseenter`** —— 使用者會立刻看到一次方向相反的預覽。這是認知負荷最重的一種形式（「我剛按完，它為什麼又在示範相反的事？」）。

規則：**游標自上次點擊後必須移動過，hover 預覽才算數**。實作是一個 `moved` 旗標，任何點擊設 `false`，任何 `mousemove` 設回 `true`。效果等於「必須先離開再回來」。

## 7. 分岔（union 分支）

- **分支的身分是「形狀」（標籤序列），不是 tag+idx。** 否則 `li[1]` 與 `li[3]` 會併成兩條畫起來一模一樣的冗餘分支。序號相異時該層自然 `forced` bare —— 跟共同結尾的處理完全一致，不是特例。
- 分支上只有一個動作：**刪除（🗑，放在分支列左緣）**。不做「停用」—— 停用會讓有效範例掉到 1 個，破壞「至少選兩個」這條貫穿全工具的規則。
- 刪除會連同該分支綁的所有範例一起走，所以**刪到剩不足 2 個範例時垃圾桶失效**（灰掉）。
- **新增分支：分歧槽下緣的 ＋。這顆按鈕即使沒有分岔也必須在。** 「漏抓就再點一個範例」正是要在沒有分岔時把第一條岔路生出來；把 ＋ 藏在分岔裏會變成雞生蛋，等於廢掉 §1 選 union 的核心理由。沒有分岔時分歧槽不畫括號，只留 ＋。
- 一側耗盡的分支畫成「（直接）」。

## 8. 加範例

union 骨幹的失敗回復路徑就靠這個，是主線不是加分項。

1. `phase = 'add'`，只 push `examples`，**不動** `overrides`／綠框／▼ 位置
2. `ncaOf` 是 N 元的
3. hover 預覽：點下去之前就看到「12 → 20 筆」
4. **二次確認的判準不是「共同結尾有沒有縮短」。** 還沒有分岔時，任何不同形狀的新範例都必然讓共同結尾縮短 —— 而那正是主要復原路徑。每次都跳確認等於把警告稀釋掉。真正該擋的是**會毀掉東西**：

   ```
   destructive ⟺ 紅框被迫移位（m.rUp ≠ G.rUp）
              或 使用者調過的某顆開關在新幾何裏不復存在
   ```

   什麼都還沒調就加變體 → 一次點擊完成；調了半天才加 → 才跳確認。
5. 右鍵移除紅框**不依賴 `G`** —— 配對失敗（`G === null`）正是最需要它的時候。

## 9. 預覽列表

Panel 下方一列一筆，只顯示前 N 筆（`LIST_N = 12`），不捲動。

### diff 以「抽取結果」為基底，不是以節點身分

拿 DOM 節點做 Set 比對會產生假變化：紅框從 `span` 移到它的 `a`，8 個元素全換、但每一列文字一模一樣 → 畫面上 8 刪 8 增。**列表是抽取結果的預覽，就該用抽取結果來 diff。**

- 用 `getTxt(el)`（已 normalize + trim）當 key，重複文字走**多重集**計數比對
- 兩邊文字序列完全相同時顯示「共 N 筆 · **無變化**」，**不顯示箭頭** —— 「這個動作不改變你抽到的東西」本身就是使用者最想知道的答案

| 狀態 | 畫法 |
|---|---|
| 目前命中 | 正常列 |
| 預覽會新增 | 藍底 |
| 預覽會消失 | 淡化 + 刪除線，**位置保留不重排** |
| 你選的範例 | 左緣紅色細條 |
| 無文字 | 顯示 `(空)` |

每列：**◎（捲到該元素）+ 序號 + 文字**。捲頁掛在 ◎ 上，不掛整列 —— 整列可按會讓它宣稱自己是控制項。**列本身沒有 hover 效果。**

底部一行寫成「共 12 筆 → 18 筆」而不只是「18」—— 新增的列可能全在前 N 之外。

## 10. 面板數字

**整個面板只留一個數字**：底部的「命中 N 筆」。hover 任何 pill 或拉桿時就地變成預覽值。

v2 在每顆開關兩端、分歧開關、chips 上都掛命中數，一個中等複雜的查詢式會有十幾個數字在競爭注意力，而且大多數時候都一樣。資訊量沒損失（一次只 hover 一個東西），畫面從十幾個數字降到一個。

## 11. 框線

`*{box-sizing:border-box}`，2px border 畫在框內，所以 `pad` ≠ offset。

| 框 | 語意 | 實作 |
|---|---|---|
| 綠 | 完全在外 | `p = +3` |
| 藍 | 騎在邊框上 | `p = +1` |
| 紅 | 在裏面 | `p = 0` + `background: rgba(red,.10)`，**不畫 border** |

三者是**三種不同的編碼**（外環／邊線／填色）而非三個同心環：範例元素同時也是命中元素，同心環會變成相距 2px 的平行線，看起來像算圖瑕疵；而填色在任何尺寸下都成立。

### 畫布永遠只畫「一個狀態」

有預覽時藍框就是**預覽後**的集合，實線，直接搬過去；沒預覽時就是當前集合。**畫布從不畫兩個狀態的差** —— 虛線代表增刪是一整套要學的視覺語言，認知負荷最高，不該是預設。增刪的差只活在下方列表。

視覺語言的認知負荷分級（由低到高）：

1. hover 元件有視覺變化 = 這東西可以按
2. 拖曳觸發預覽 ／ 預覽顯示在列表 ／ hover 觸發預覽（需先離開才能再觸發）
3. hover 觸發預覽，且點擊後立刻反向觸發
4. 畫布上用虛線表示增刪

v3 停在 2。3 用 `moved` 旗標擋掉，4 不做（未來可當進階選項）。

## 12. 輸出

**一條字串**，不是 v2 的兩行（`綠框: …` + `判斷式: …`，使用者得自己接）。

**畫面即輸出，沒有第二種表達式。** 不做「嚴謹式」：它只是換一種無聲失敗（寬鬆式改版後多抓垃圾；嚴謹式改版後序號整排位移抓到錯的東西），不值得多一條要維護的路徑和「複製出來的跟看到的不一樣」的認知落差。

**已知代價**：v3 只能產出對當前頁面的最小式，無法手動加上「今天不划算、明天才擋得住雜訊」的 predicate。接受。

### 錨點

複製輸出真正的弱點不是 predicate，是綠框錨點。v2 的 `absPath` 每層都帶序號（`/html[1]/body[1]/div[3]/main[1]`），頁首多一個 banner 整條就報廢 —— 在錨點還是全序號絕對路徑的前提下爭論 predicate 嚴謹度是優化錯的那一端。

優先序：綠框或最近祖先有 `id` → `//*[@id="x"]/…`；否則夠獨特的 class → `//*[contains(@class,"y")]/…`；都沒有才退回全序號絕對路徑。（`label()` 已在算 id/class，資料現成。）

**錨點不做成可調** —— 它沒有「多抓少抓」的連續光譜可以預覽，做成互動元件既無 hover 預覽可搭，也違背極簡目標。複製後的 toast 把整條字串秀出來讓人看一眼即可。

## 13. 不變量與可刪除的東西

**命中數永遠 ≥ 範例數。** 兩個紅框在任何可達狀態下都被自己那條分支命中：序號相異時 `forced` 強制 bare，序號相同時 idx 也中。
→ 查詢式求值本身不會回 0。

但有兩種**幾何／定址**失敗仍然可達，而且必須出聲，否則使用者只看到空面板：

| 狀態 | 條件 | 訊息 |
|---|---|---|
| 幾何失敗 | `validStops` 為空 —— 這些元素在任何一層都對不齊 | 「無法建立查詢式 — 右鍵紅框可移除重選」 |
| 定址失敗 | `matched.length < examples.length` —— 打破上面那條不變量 | 「有元素無法用 XPath 定址（多半是 SVG 內部）」 |

### SVG 不可用標籤名定址

實測：`./span/svg` 回 **0 筆**。SVG 元素在 SVG 命名空間，XPath 1.0 的無前綴 name test 匹配不到（`./span/*` 和 `local-name()` 才行）。

所以**選取一律夾到包住 svg 的那個 HTML 元素**（`pickable()`），並額外擋掉任何不在 XHTML 命名空間的元素（`<foreignObject>` 之類）。要真的支援抓 icon，得讓查詢式長出 `*[local-name()="svg"]`，那會同時污染表達式與抽象化 pills —— 等真的需要再說。

**每個動作都是自己的反函數。** 拉桿拖回去、序號片再點一次、分支再啟用一次，全部完全還原。唯一例外是破壞性的第三範例 —— 而那正是唯一放了二次確認的地方。
→ **v3 不需要 undo 系統。**

**v3 相對 v2 刪掉的**：`//` 開關、`skipDiverge`、子輪廓 chips (`shapeOn` / `childTags` / `matchesIfChip`)、`noQuery` 狀態、「為何」欄、每顆開關的命中數 (`.n`)、無文字警告文字、無命中錯誤態、由上往下的表格版面。
